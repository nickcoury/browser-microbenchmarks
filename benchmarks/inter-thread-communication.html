Inter-Thread Communication Chaos Matrix

Measures round-trip throughput between main thread and Web Worker(s) under increasing concurrency. Simulates the worst-case anti-pattern: N independent code modules all firing uncoordinated bidirectional messages. Each round-trip modifies data on both sides.

Approaches tested: Structured Clone, Transferable, MessageChannel (1:1 ports), BroadcastChannel (pub/sub), SAB + postMessage (shared memory + message notification), SAB + Atomics (lock-free sync), Comlink Proxy (RPC wrapper overhead), Dedicated Worker Pool (1 worker per caller), Transferable Streams (piped backpressure).

Fast (>10k rt/s) Moderate (1k–10k rt/s) Slow (<1k rt/s) N/A (not supported or failed)

Methodology

  • Round-trip = main sends data → worker modifies → worker replies → main receives.
  • Sequential (concurrency=1): one caller awaits each round-trip before starting the next.
  • Chaos (concurrency=N): N independent loops each fire round-trips as fast as possible for the duration.
  • 1 KB payload: object with a 1 KB Uint8Array; worker touches every byte.
  • 1 MB payload: object with a 1 MB Uint8Array; worker touches header + 16 samples.
  • Transferable: ArrayBuffer ownership moves each direction (main→worker→main).
  • Comlink Proxy: Simulated RPC via MessageChannel — method call serialized as {method,args,id}, response proxied back.
  • Dedicated Worker Pool: Spawns exactly concurrency workers, each serving exactly one caller.
  • Transferable Streams: WritableStream → worker → TransformStream → ReadableStream back to main.
  • SAB requires cross-origin isolation headers (not present on GitHub Pages) — shown as N/A if unavailable.
